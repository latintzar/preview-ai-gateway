# Security boundaries

- Visitor keys enter through a TLS password window on the dedicated gateway origin. The field clears after submission. Keys stay in server memory for at most ten minutes, bounded by the thirty-minute session lifetime; an idle cleanup loop prunes expired material every second. Deletion/startup/shutdown erase the mutable session buffer. In-flight requests can finish within their deadline.
- Python, the TLS proxy and HTTP client necessarily hold temporary key copies. Complete heap zeroization is not promised. The operator/TLS host is trusted; dumps/debuggers can inspect process memory. The implementation provides no key retrieval endpoint and persists no visitor key.
- Use the supplied no-access-log server invocation and disable body/header/query logging on the gateway proxy. Keep tracing/APM request-body capture disabled. Application errors contain fixed messages; provider body/header/error text is discarded. Diagnostics expose booleans/counts only.
- A separate random IP-hashing salt is stored beside the ledger as `<ledger-name>.ip-salt`, in its owned mode-0700 directory with an owned regular mode-0600 file. Its stable hash preserves SQLite IP-rate history across restarts. Session secrets remain disposable. Salt creation is locked and durable; unsafe links, permissions and partial nonempty state fail closed.
- Cookies are Secure, HttpOnly, SameSiteStrict, host-only and path `/`. Exact Origin, CSRF, project-origin binding, JSON-only bodies and fetch-site checks protect mutations. Sessions are random, capacity-bound and disappear on restart. CORS contains explicit origins with credentials; no wildcard is used.
- The provider host, model snapshot, instructions, output bound and tool prohibition are server-owned. Text inputs can still contain prompt injection; registered tasks get no provider tools, account data, URL fetch capability or business writes. Consuming apps validate results and render text safely.
- Shared spending defaults to disabled. Only a operator-owned `ATELIER_OPENAI_API_KEY` can fund it. Other company/global provider variables are ignored. The approved $2 ceiling is in source and cannot be raised by public request fields or operator configuration.
- Reservations assume the verified model contract and rate ceilings. Provider billing, price changes, taxes and unrelated account usage lie outside this local ledger. Use a dedicated provider project and its available account limits as a second boundary; reverify the expiring rate card before shared activation.
- Timeout/unknown holds persist, including across days and restarts. Reconcile them only from an authenticated provider usage receipt for that ticket. There is no public refund/reconciliation endpoint. Back up the private ledger; deleting it resets accounting and is an operator trust action.

The key popup does not make an untrusted preview harmless: an allowed preview can invoke its registered tasks with a user's active session. Bound task capabilities and request rates are the containment. Verify TLS, provider entitlement and each real project integration before use.
